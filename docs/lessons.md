# Engineering lessons

Short, evidence-backed rules learned on this project. Add one only with the evidence that taught it; delete any that stop
being true. This file is technical (code, hardware, tooling); how we work is kept elsewhere.

| # | Lesson | Evidence | Check that catches it |
|---|---|---|---|
| 1 | **Host tests do not see the C5.** Flash and measure after every structural change. | Draw time rose 11 -> 15 ms after the canvas refactor (runtime stride, per-pixel clip, a real `div` per pixel); only the unit showed it. | `tools/bootprobe.py` frame timing; `make -C sim bench`. On the engine build the screen blanks shortly after boot, so the probe's `[eng]` lines are only the boot transient: keep the screen awake (touch it) or read `draw_avg` and `fps` from perf.csv |
| 2 | **Free-space queries on FAT are a stall.** `SD.usedBytes/totalBytes` walk the FAT. | 8,432 ms at boot on a 29 GB card. | grep for `usedBytes|totalBytes|f_getfree` must be empty |
| 3 | **Internal RAM is the scarce resource; PSRAM is not.** | Boot heap fell 61 -> 41 KB over a day of features; moving about 36 KB of buffers to PSRAM restored 77 KB. | boot heap line in `bootprobe.py`; floor 55 KB |
| 4 | **The boot panic depends on the exact binary.** | `s_psram_chip_init` illegal-instruction panic on 66dc86c and 862b4e1, clean on 29cf577 and da32447 (14-byte difference). | 12-reset probe on the exact build you ship |
| 5 | **Unsigned time compares break at the wrap and on timestamps from the future.** | Row-hold release bug; twin-budget refill via a backwards timestamp; millis wrap. | use `(int32_t)(now - then)`; test wrap and future stamps |
| 6 | **Anything that caps or budgets an attacker-reachable resource needs an adversarial-drain test.** | Rollover deferral under a beacon flood; probe-limit evasion; shared twin-scan budget drain. | ask "what if the attacker spends this budget first?" |
| 7 | **A rewrite-the-whole-file logger stalls as the file grows.** Append in bounded batches. | 1 s at 2.5k rows to 64 s at 8k+; the unit froze and the power was pulled. | `sd_max` column in perf.csv stays flat |
| 8 | **Opening a serial port resets the board** (the CH340, and the Waveshare's native USB-Serial-JTAG). A reset also ends a recording in progress and loses the up-to-3 perf rows still in RAM, so stop recording before pulling logs. Wait for the banner before sending, and space port opens at least 8 s apart: a reset 1.5-6 s after boot, while packs load, makes the boot-loop guard skip that pack until its folder is removed for one boot. | Test commands sent into a booting unit were lost; sdput, bootprobe, esptool and the designer flagged `new-theme` and `my-baph0mau5` several times. | `tools/bootprobe.py` / `tools/sdput.py` wait for the banner; do not run bootprobe with real packs on the card |
| 9 | **Arduino's SD flush ignores fsync errors.** Verify the size after a write. | Review of the append logger. | size check after close in the logger |
| 10 | **Check what the checksum in a "known good" fixture really is.** | A brief's `$GPRMC...*53` was wrong; correct is `*73`. | compute the NMEA XOR in the test |
| 11 | **A shared gitignored baseline goes stale silently.** Keep real copies per worktree and refresh deliberately. | All 9 regress images differed on an untouched base. | `make -C sim regress` against a known-fresh copy |
| 12 | **Write the test first and watch it fail**: several fixes were found by tests that "never ran red". | Reviewer mutation runs on the FILES and GPS work caught tests that did not bite. | mutate the fix, expect failures |
| 13 | **A fixed stack limit surfaces as a vague failure.** Read the panic backtrace before theorising; check `uxTaskGetStackHighWaterMark` after adding a deep call path. `SET_LOOP_TASK_STACK_SIZE` must be at global scope (inside a namespace it silently does nothing). | sdput END answered "no reply": loopTask's 8184 B stack overflowed (peak ~8.25 KB, Stack protection fault in `_svfprintf_r`); fixed with 12 KB off the Waveshare (5cf83a1, 5ca2978). | high-water mark logged on the console path after a change |
| 14 | **Host stubs and fixtures drift from the firmware.** Run `make -C sim test` after adding any firmware `#include`, and write fixtures against the constant (`themepack::MAX_PACKS`), not its value. | `<esp_heap_caps.h>` broke `test_active_discovery` (53bc5db); `MAX_PACKS` 8 to 12 failed `test_palette` and `test_radarclip`, which hard-coded 8 and an 800 B bound. | `make -C sim test` before every commit that touches includes or limits |
| 15 | **The Waveshare flashes with `esptool --no-stub`, not `pio -t upload`** (the stub's write times out). Offsets: 0x2000 bootloader, 0x8000 partitions, 0xe000 boot_app0, 0x10000 firmware; `--chip esp32c5 --baud 115200 (460800 also worked three times with `--no-stub`: 4,060,160 bytes in 34 s) --before default-reset --after hard-reset --flash-mode dio --flash-freq 80m`. | `pio upload` failed repeatedly with a pySerial "Write timeout"; the esptool command worked every time. | the command is the check |
| 16 | **`diag.log` and `perf.csv` share no key, so matching a boot to its perf rows is a guess until two markers agree.** Check at least two independent ones (the time of a heap-min dip, a stall length, the REC times) before quoting numbers, and say when the match is a guess. | A long recording was matched to the wrong perf run because a log rotation (8,977 to 8,987 s) landed next to REC at 8,979 s; BLE and draw numbers and a "perf log stopped at 13,089 s" problem were reported and retracted. The right run showed the heap-min dip at t=3,050 s, matching diag's warning at 3,041 s. | `tools/perf_report.py` prints a per-boot table; a boot counter column in both logs would remove the guess |
| 17 | **A parser that silently drops lines reports "nothing there".** After parsing a device listing, compare parsed entries against raw lines. | The `SDLS` size column was `%8lu`, so an 8-digit size had no leading space and a filter keyed on it hid the 16,776,796-byte `probes.csv`; the listing said no drive was recorded (55901dd). | `tools/sdpull.py` parser, tested with the 8-digit case; the column is now `%10lu` |
| 18 | **A writer that invents a new filename pattern must be added to every classifier and allowlist.** | Rolled-over `probes-2.csv` returned `None` from `capturepaths::classify`, so `SDDEL` and the FILES screen could not delete a file holding probe MACs and SSIDs; found by an automated security review (29a8887). | `test_evidence_csv` asserts every part the writer produces classifies; grep `classify(` and `delPolicy` when adding a name |
| 19 | **The Waveshare 3.5" J3 TX/RX pads are not connected to the chip.** Wire a UART GPS to GPIO0 or GPIO1 (pads 15 and 17). | A GPS wired to the labeled TX/RX pads (26 and 28) read 0 bytes for the whole session; the schematic routes `U0TXD` and `U0RXD` through `R56` and `R59`, marked `0R_NC` (not fitted). | `docs/WAVESHARE-35-J3.md`; `GPS` console command shows bytes and sentences |
